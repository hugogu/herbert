# 进阶课程的解题分析与设计

2026-10-08。先研究社区 #0001–#0020，再独立设计 L31–L50。借鉴的是 H 的机制、压缩路径的方法与视觉组织原则；没有把社区棋盘换名、旋转或拼接后用作原创关卡。

## 实际试解与证据边界

对前 20 题读取完整棋盘，做安全格连通分析，并尝试固定循环、增长指令参数和双指令参数的候选程序。**8 题找到原 byte 上限内的解**，都通过本项目引擎与固定版本的 HOJ Ruby 判题器；其余 12 题尚未找到上限内的解。下表的空间分析不等于已经求出这些题的算法，更不声称找到最短解。

独立找到的程序在[测试资源](../Tests/HerbertCoreTests/Fixtures/community-study-solutions.json)中，仅用于回归，不会打包进任一应用。`swift test` 验证原预算与通关；`ruby scripts/check_hoj_reference.rb /path/to/hoj` 可复查两端一致性。

不踩陷阱的连通分析显示，20 题的全部目标都能从起点到达。这只证明存在安全路线；**难点在于把路线压缩进 byte 预算**，不是找一条任意长的路线。

两个具体例子说明，题目不能按目标数量、源代码长度或参数数量直接排序：

- #0014：`a(X):Xra(Xs)`，最后一行 `a()`。第一个参数为空；随调用增长的指令串与墙一起决定实际位移。程序为 8 byte，不能写成“数值小于零退出”的普通循环来解释。
- #0009：`a(X,Y):XXa(XY,Y)`，最后一行 `a(l,srsl)`。一个参数是增长中的组合动作，另一个是追加单元；两次执行组合动作，生成菱形中的遍历。此解为 15 byte，原记录最佳为 11；没有声称重现最佳解。

## 新题的梯度

保留 L01–L30 的编号、棋盘、预算和存档语义。L31–L50 增加四章，每章五题；新机制从相对独立的空间例子迁移到复杂组合。不是保证每个人感受到的每一题都严格更难，也不是把参考解中的过程数当作唯一可用算法。

| 关卡 | 主要推理负担 | 墙与视觉结构 |
| --- | --- | --- |
| L31–L32 | 有限次数、交替转向、超量前进与往返同步 | 退进船闸、不同高度的管风琴；端墙直接参与执行 |
| L33–L35 | 双尺寸变化、次数/长度/转向三参数、子程序结束朝向 | 收缩回廊、交错悬臂、带弯口的四向风车 |
| L36–L37 | 指令参数交换、反向变化的数值参数、递归返回 | 编阶与四向反向阶梯；不能只靠固定单元向前走 |
| L38–L40 | 调用前/后的动作、两个子分支、互递归交换尺寸 | 折页花窗、灯树、相向庭院；墙分开相邻层与分支 |
| L41–L42 | 重复器嵌套、数值职责交换、连接动作交替 | 十六扇格窗、非单调跨度的换位通道 |
| L43–L45 | 四分递归、旋转参数互换、选择展开层、深度与间距分离 | 递归灯宫、融雪方印、灯窗图谱 |
| L46–L47 | 两过程互递归、构造逆过程、逆序与左右交换 | 龙曲与四向龙纹；折返后才进行下一次旋转 |
| L48–L50 | 深度/距离/旋向三参数、分杈折返、多层过程约定 | 旋向树冠、穹顶镶嵌、星穹圣殿；几何对称揭示可组合单元 |

全部新题有墙，且墙紧邻实际安全通道。L31/L32 的参考解故意撞墙；去掉墙后同一程序不能通关。其余题的墙限制抄近路并提示层、房间、分杈或旋转单元。L44 的四个对称陷阱端点限制错误超行，其余新题不依赖踩陷阱。

## 避免“看起来复杂”

先用独立几何路线生成目标与通道边界，再用真实 H 引擎和 Ruby 参考引擎重放程序。测试核对通关、byte、位置、朝向、指令数、撞墙和陷阱次数；几何路线不会解释 H 程序，因此能发现过程排列或参数传递错误。

还用有限候选搜索探测短固定循环。初版 L37 被 `a:srsla` / `a` 解掉，初版 L44 被 `a:ssslslsla` / `a` 解掉，明显弱于设计意图：

- L37 改成四向往返阶梯，要求结束状态能支持下一方向。
- L44 在四个对称端点增加陷阱，限制把墙当作无限试探器的固定节奏。
- 回归测试检查这两个已知候选进入未通关的重复状态，而不是只跑固定步数就说“无解”。

搜索只能排除所测候选，不证明最优解，也不证明只能用提示建议的算法。更短、更巧的有效解仍欢迎提交；难度尚待真实玩家试测校准。
