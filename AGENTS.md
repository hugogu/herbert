# Herbert

- SwiftUI universal app (iOS 17+, macOS 14+); `HerbertCore` is a local Swift package with no UI dependencies.
- Original rules: http://herbert.tealang.info/rule.php. Language is H, not a generic turtle language. Count letters and numeric literals (12 is one byte); punctuation is free. Preserve 25 × 25 boards, walls, traps, and original IDs/limits.
- All progress goes through `ProgressRepository`. Keep cloud credentials out of clients. Future Cloudflare D1 access must be through an authenticated Worker.
- `swift test` runs unit/integration tests. `python3 scripts/generate_project.py` regenerates the checked-in Xcode project. `scripts/check.sh` formats/lints and tests.
- Original public Flash client loads boards with POST `action=problem` to `problem.php?id=N`; a response contains a 625-character map and byte limit separated by a newline. A plain GET yields HTML. Some requests to this old HTTP server stall; use bounded retries and validate every cached response.
- This machine has the iOS 27 Simulator runtime (iPhone 18 Pro Max, iPad Pro 13-inch (M5)). Simulator runs are not real-device validation; say which one was used.
- In native Mac UI tests, SwiftUI static text can expose its content through accessibility `value` rather than `label`; assert the visible value with a label fallback.
- Under Swift 6 isolation checking, value-type `Animatable.animatableData` must be `nonisolated` when the drawing also conforms to SwiftUI `View`.
- AppKit drawing needs an RGBA bitmap context; export icons through an opaque Core Graphics context to produce RGB PNGs without alpha. Fail generation explicitly if the drawing context cannot be created.
- README screenshots must be actual app captures. `scripts/capture_screenshots.sh` runs an opt-in native UI test and exports window/board attachments; ordinary UI runs skip that capture test. Keep original problem credits and the separate content licensing notice.
- If SSH publishing stalls, pass the HTTPS repository URL directly to `git push` while retaining the saved SSH origin. `remote.<name>.url` accepts multiple values; a command-line `-c` addition can still leave a push using the configured SSH URL. Verify the published commit SHA afterward.
- Native XCTest screenshots, including window captures, can include overlapping windows. Activate the app before ordinary captures; for inactive-window color checks, position the tested actions clear of the foreground application's windows and verify there is no overlap. Inspect every exported image, especially board-only captures.

- Native Mac Canvas can expose its descriptive state only through accessibility `label`; use that for board assertions. Rebuild in a fresh DerivedData directory if newly added Swift package localization files are absent from the embedded resource bundle.
- Match screenshot UI language to its README. The capture script defaults to English (`docs/screenshots/en/`); pass `zh-Hans` for the Chinese assets.
- macOS can restore the app without an open window. Native UI tests should open New Window with Command-N if no window appears, then wait for it before choosing the display or checking the library. Window menu targets may not be ready immediately after Command-N.
- XCTest screenshots can fail to create images on a secondary display. The optional `TEST_RUNNER_HERBERT_TEST_DISPLAY` selects a destination via the native Window menu. Cache the menu item frame and click relative to the window: the item identity changes on hover, and the application frame can be infinite. Avoid relying on restored window placement.
- `HerbertCore` bundles only the 50 MIT-original lessons; community JSON belongs in optional `HerbertCommunity`. `HerbertAppStore` must never link that module. Audit the final .app with `scripts/check_app_store_bundle.py`, including archives, rather than relying on UI filtering.
- Original lessons display continuous L01–L50 numbers, independently of internal save IDs. L07/L08 use 10051/10052; L04–L06 use 10074–10076, L10–L30 use 10077–10097, and master lessons L31–L40 use 10098–10107; synthesis lessons L41–L50 use 10108–10117. IDs 10017/10022/10024, 10030–10050 and 10053–10073 are retired. Never apply a retired completion to a redesigned board. Generate lessons/translations/test references with `scripts/generate_original_problems.py`; reference solutions must stay outside application resources. Preserve community IDs and existing saves.
- Personal signing belongs in ignored `Config/Local.xcconfig`, included by `Config/Signing.xcconfig`; project regeneration must not commit or erase a developer's local team selection.

- Community board symbols are `x` = wall and `*` = trap; do not infer them from their appearance. The pinned HOJ interpreter/sample judge audit is in `docs/hoj-compatibility.md`. Keep normalized command/byte fixtures aligned using the optional `scripts/check_hoj_reference.rb` without vendoring the reference source.
- Modern walls are translucent; pixel checks at cell joins should compare against a point away from the underlying grid dot. Trace wall contours with opposite winding for holes and separate diagonal components.

- Advanced course uses independent geometric command oracles in `scripts/open_course.py` (L11–L22) and `scripts/advanced_course.py` (L23–L30). Each wall/trap count in L04–L06 and L10–L30 is 15–30% of the complete route-border capacity; validate safe connectivity and alternative traversals. Author obstacle landmarks independently; do not wrap new reference routes in `outline()`. L23–L30 retain their target/start geometry. Preserve literal turn expansion in those oracles: `rrT` flips the effective turn but adds two executed instructions every recursion; simplifying it to `l` makes exact instruction-count tests wrong.
- Run native GUI and CLI UI tests sequentially: they share focus and can redirect each other's input. Xcode can rewrite shared scheme XML when a project is open; close the project and regenerate before checking generated-file consistency.
- Mac DMG builds must pair `CODE_SIGN_INJECT_BASE_ENTITLEMENTS=NO` with explicit `Config/MacPreview.entitlements`: disabling injection alone also removes the sandbox. Audit the mounted app's actual entitlements, architectures and catalogs with `scripts/package_macos.py`; ad-hoc signatures are not Developer ID signing or notarization.
- AI Battlefield is a separate UI-independent Swift package. Never encode API keys into settings, history or share images; the app keeps keys in Keychain. Preserve SSE blank-line boundaries with the byte parser: `URLSession.AsyncBytes.lines` can omit them on Apple platforms. Test the actual HTTP stream, not just pre-split event fixtures.

- `HerbertStrings.text` / `L10n.text` already applies printf arguments: pass values directly, never wrap it in a second `String(format:)`. Avoid identifiers on UI container groups when their children need distinct XCTest identifiers; SwiftUI can propagate the container identifier.

- The current course has L01–L10 introductory lessons, L11–L30 advanced lessons, L31–L40 master lessons, and L41–L50 synthesis lessons (50 originals). Never reuse retired lesson IDs; inert old progress records remain importable. Public Battlefield teaching examples are separate from scored puzzle reference fixtures.
- macOS sandbox/TCC may deny the app container even to an escalated terminal. Python `Path.glob()` can silently yield no files on that denial; use an explicit directory read before concluding history is empty.
- Do not overlap native UI test runs or native computer-use sessions; they share focus and accessibility state.

- Mac Battlefield sheets use an AppKit bridge to enable resizing and set the initial content size once after attachment; SwiftUI min/ideal frames alone can open a scroll-backed sheet at its minimum width. Do not reset size on live result updates. Test both dimensions and three visible model columns.
- Battlefield dashboard columns use `CompetitionResult.ranked(keepingTiesIn:)`, not `ranked`: `ranked` breaks score ties by live token counts, so columns swapped every second during a match and a tap could land on another model's button. While running it sorts by score only and ties keep the order last shown; finished results, share images and history keep `ranked`.

- SSE wire framing can exceed 4 MiB before a 64K-token completion finishes. Bound individual events and decoded answer/reasoning bytes independently; do not cap cumulative SSE metadata. Apply the judge parser size limit after extracting the fenced H program.

- Add manual UI translations before the `// Original curriculum` marker in each strings file; the course generator replaces everything from that marker onward. Verify regeneration before committing new strings.

- Give parsers with private stored state an explicit initializer when tests customize limits. CI uses an older Swift toolchain than this machine; do not rely on newer synthesized memberwise initializers.

- Streaming providers can return HTTP 200 with `finish_reason: error` or an in-band error. Preserve partial output/usage and stop before judging; retained reasoning does not prove generation is still active. Keep request inactivity timeouts separate from total resource deadlines, which can interrupt streams that still emit data.

- SwiftUI Toggle identifiers can also match an outer container with no accessibility value. In UI tests, select the native checkbox/switch before asserting or changing its value; use the same lookup after relaunch to verify persistence.

- Keep a popover's presenter unique across adaptive layouts. Binding the same popover to multiple `ViewThatFits` candidates can dismiss it immediately; use `AnyLayout` to rearrange one control tree. Wait for popover disappearance before capturing screenshots.

- Avoid async closure literals in public default arguments: older Swift toolchains can emit conflicting async context layouts across library/client modules (swiftlang/swift#92017). Construct the default inside a library-owned initializer overload. Test real default cooldown cancellation as well as injected sleeps.

- A Battlefield answer cell is a plain Button with its action (cancel while generating, otherwise retry) drawn over it at the trailing end of the first line. Its label's contentShape must cover the whole cell, or blank space won't open the answer, except a 44 pt square around the action (`eoFill`). iOS hit testing weighs the size of a touch: a button over another button, or over a tap gesture, loses taps even at its center unless the view below leaves room around it. A Mac UI test passing says nothing about this. The trailing end was the user's choice (Oct 2026): beside the status title the target covers the middle of the cell.
- Battlefield repositories encode dates as milliseconds since 1970. Normalize expected values through that date strategy when comparing complete disk round trips; in-memory Date precision can differ slightly.

- App Store listing files live in `store/`; `scripts/check_store_metadata.py` enforces App Store Connect limits. Since iOS 27 the required iPhone screenshots are the 6.3-inch medium display (1206 × 2622 from the iPhone 18 Pro simulator); 6.9-inch images are optional and fail the required slot as an invalid size. Keywords allow 100 bytes (a CJK character is 3), and each keyword must be longer than two characters. The store name must start with the Home Screen name.
- `scripts/capture_store_screenshots.sh` runs the opt-in `StoreScreenshotTests`. XCTest returns landscape iPad screens in portrait pixel order, turned clockwise; the compositor rotates them. `simctl status_bar --time` accepts only an ISO time with milliseconds, such as `2026-01-09T01:41:00.000Z`.
- Native Mac UI tests take over the mouse and keyboard; ask before running them while the user is at the Mac. They fail with "Timed out while enabling automation mode" on a locked screen; check `ioreg -n Root -d1 | grep CGSSessionScreenIsLocked` first. After a failed UI test, xcodebuild can hang for minutes past "TEST EXECUTE FAILED".
- On iPhone, the keyboard and pinned Run controls cover an editor in the lower half of the lesson. UI tests should scroll the editor header to the top before typing. On iPad, wait for the keyboard reflow to settle (`waitForStableFrame`) before tapping editor controls.

- Battlefield UI tests open sidebar `section-*` items, so run them on iPad or Mac; iPhone's tab bar has none. On the iPad simulator eight of them also fail on main: iOS reports static text `value` as `""` rather than nil, so `value as? String ?? label` never reaches the label; text fields keep their old text before typing; some sheet buttons need scrolling. Compare failures with a main baseline before attributing them to a change.

- MiniMax can put its entire `<think>` trace in the final-response field. A saved L05 response had 388,735 characters and 12,182 lines; measuring it as one SwiftUI `Text` saturated the main thread in CoreText and drew blank. Keep raw responses intact and display bounded, lazily loaded text blocks in the same continuous scroll. In UI tests, scroll before looking up a block that has not been loaded yet.
- The 3D board style is a SwiftUI `Canvas` painter (`Herbert/Views/Board3D/`), deliberately not SceneKit (deprecated) or RealityKit (`RealityView` needs iOS 18). Its camera, framing, draw order, occlusion and interaction rules live in `HerbertCore` (`BoardCamera`, `BoardCameraRig`) with unit tests; `BoardCameraRig` stores the turn relative to a home angle that depends on the view's aspect (nearly straight on below 1.15, diagonal above). Keep new 3D rules there, not in views.
- To iterate on the 3D look without launching the app, build a scratch Swift package that depends on this package by path, symlinks or copies `Board3DPalette/Pose/Painter/Drawing` and renders `Board3DDrawing` with `ImageRenderer` to PNG (use a fresh renderer per frame; it caches). Benchmark with a release build: the debug build is several times slower and says nothing about blur or drawing cost.
- Pass `-board.style threeD` as a launch argument to open the simulator app in 3D: argument-domain values reach the UI-test preferences suite, while writing a plist into the app container does not. The first tap right after `simctl launch` is ignored, so wait a moment.
- On iOS, SwiftUI drags over a board inside the page `ScrollView` swallow vertical swipes. `Board3DInput` uses UIKit recognizers whose delegate refuses vertical-dominant drags so the page scrolls; the 2D board still has the old behavior. XCUITest `swipeUp()` on an element starts at its bottom, which can sit under the pinned run controls and silently do nothing; drag from a visible point instead.
- The page behind the enlarged 3D stage stays in the accessibility tree for XCUITest (`accessibilityHidden` does not remove it), so the stage's controls use `stage-` identifiers. On a phone the board legend sits below the fold under the pinned controls: scroll before tapping `board-legend`. `testBoardGuideExplainsWallsAndTrapsInEveryLanguageAndStyle` and `testBoardSettingsPersistAndTrailCanBeHiddenWithoutLosingMoves` already fail on the untouched 1.0.0 code on the iOS 27 simulator.
- Landscape iPhone captures arrive turned the same way as the iPad ones; `sips -r 270` makes them viewable. Run only one `xcodebuild test` at a time per simulator and give each its own log file: overlapping runs interleave output and make results unreadable.

- Validate cloud development with the actual Wrangler entrypoint as well as imported-handler fixtures: ordinary constants cannot be exported from a Worker entry module. Custom native Info.plist keys need an explicit template; `INFOPLIST_KEY_HerbertLeaderboardURL` alone was omitted by Xcode. Verify the endpoint in the built bundle. Local Wrangler scripts force `--local --env=`; staging/production bind separate D1 databases and Apple App IDs. See `docs/development.md`.

- `worker/` owns the verified leaderboard API and numbered D1 migrations. Never trust submitted scores/identities; replay canonical originals. Native/Worker parity fixtures come from `swift run HerbertJudgeFixtures`; run Worker checks/tests with Node 24. Use the versioned Cloudflare Access admin API for a separate management project, not direct business-table writes.
- `HerbertCloud` links only into `HerbertAppStore`. `HerbertLearning` excludes cloud, Battlefield and community modules at compile time; audit both Mac and iOS products with `scripts/check_learning_bundle.py`. Education metadata does not establish a Mainland game-approval exemption.
- A locked Mac can make XCTest fail with "Timed out while enabling automation mode" before any test runs; confirm an unlocked desktop before native UI verification. Do not mistake that initialization failure for an app assertion failure.
- General App Store UI tests use `--ui-testing-cloud-offline`; account tests use the explicit preview fixture. Ad-hoc rebuilds can trigger a real Keychain authorization prompt when a developer's signed app shares the bundle ID. For isolated local regression runs, override `PRODUCT_BUNDLE_IDENTIFIER` on the xcodebuild command without changing the checked-in project or granting access to the real session.
- For prefilled editors, use an identifiable draft with `sheet(item:)` and editor-owned `@State`. A boolean sheet capturing parent state can show the current text binding while its computed Save validation still uses the old empty value; assert Save is enabled on first presentation.

- Native XCTest can be blocked by a System Settings input-source permission sheet asking to let `testmanagerd` enable a third-party keyboard. Decline this unrelated input-access request; do not grant it for app verification. Infinite element frames and later AX authorization errors can result from that sheet, rather than the app layout.

- At 50 originals, binding an ID and version per puzzle exceeds D1’s 100-parameter limit once other arguments are added. Aggregate ranking queries bind the canonical pairs as one JSON value and expand it with `json_each`; keep Worker parity fixtures and runtime catalog checks aligned with the native catalog.

- The `obscenity` filter ships an ESM wrapper over CommonJS. Worker Vitest needs `test.deps.optimizer.ssr` to bundle it, matching Wrangler; otherwise the wrapper imports an undefined default. Verify both the real Wrangler startup and workerd test suite.

- Ad-hoc sandboxed macOS previews lack an application-identifier entitlement: Data Protection Keychain add/delete return `errSecMissingEntitlement` (-34018), while a missing read can return item-not-found. Preserve readable legacy keys and fall back only for that entitlement error on macOS. `scripts/check_keychain_macos.sh` tests the real helper with isolated throwaway items and the DMG entitlements, without Mac UI automation.
